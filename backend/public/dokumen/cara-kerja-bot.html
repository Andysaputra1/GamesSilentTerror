Alur besar satu langkah bot

Satu langkah bot berjalan dari snapshot yang dilihat bot sampai chat, vote, atau aksi malam yang dikirim ke game. Halaman ini mengikuti jalur kodenya. Isi aturan fuzzy, nilai, dan alasan desainnya ada di Bedah Otak Fuzzy; di sini tidak diulang.

Yang tidak terlihat dari kode

  • Jam permainan memanggil NPCService.jalankan_bot_yang_sudah_waktunya tiap 0,5 detik. Bot yang sudah waktunya menjalankan NPCService.brain_turn. Bot yang dipanggil atau dituduh melangkah lebih cepat: catat_nlu menandai otak.segera.
  • Tahap [INPUT] sampai [KEPUTUSAN] berjalan di BrainRuntime.langkah di thread keputusan: sinkron ingatan, NLU membaca chat baru, lalu satu panggilan putuskan. Tahap [NLG] dan [KIRIM] berjalan sesudahnya di NPCService.
  • Bot tidak mengubah engine langsung. Snapshot, vote, aksi, dan chat bot lewat RoomService (lihat_untuk_bot, pilihan_bot, chat_bot), yang memegang kunci room.
  • Contoh angka satu giliran bot nyata ada di [CONTOH SATU GILIRAN].

1[INPUT]

Bot hanya melihat yang boleh dilihat kursinya: snapshot privat dari engine. Ingatan bot mencatat pengamatan baru, lalu chat baru dibaca IndoBERT sebelum fuzzy berjalan. Isi snapshot dan ingatan ada di Bedah Otak Fuzzy bagian 3.

Alur

NPCService.brain_turn
  -> RoomService.lihat_untuk_bot          snapshot_berlabel(match.snapshot(bot)): data publik + rahasia milik bot
  -> BrainRuntime.langkah
       -> Ingatan.sinkron_snapshot         catat vote Tribunal, eksekusi, pemain keluar, korban Hostage yang
                                           diumumkan, hasil Peek, pilihan malam rekan, hasil Hostage tim, chat tim
       -> baca_chat_baru                   tiap chat baru: anotasi_chat
            -> NLUIndoBERT.intent          intent + keyakinan
            -> NLUIndoBERT.target          pemain yang dituju dan relasinya
            -> pemain_disebut              chat neutral: nama yang ditulis
  -> view
  -> putuskan: pengetahuan_peran          fakta pasti dari role sendiri

Kode

Yang tidak terlihat dari kode

  • NLU tidak lagi dipanggil dari dalam Ingatan.sinkron_snapshot. BrainRuntime.langkah memanggil baca_chat_baru sesudah ingatan disinkronkan, jadi kode fuzzy tidak bergantung pada IndoBERT.
  • BrainRuntime memasang IndoBERT lewat NLUBersama, yang menyimpan hasil per teks dan konteks. Chat yang sama tidak dihitung dua kali walau dibaca banyak bot.
  • Chat dengan keyakinan intent di bawah MIN_CONF_INTENT tidak menjadi bukti (relasi_chat).
  • Chat tim hanya masuk view dan tidak pernah ke ingatan.chat, jadi tidak pernah menjadi bukti publik.

2[BUKTI]

Riwayat chat dan vote diubah menjadi angka 0–1 per pemain, ditambah konteks meja. Arti dan rumus tiap angka ada di Bedah Otak Fuzzy bagian 3 dan bagian 8; di sini cukup letak hitungannya.

Alur

putuskan
  -> hitung_bukti(ingatan, view)
       -> dugaan_status         p_sandera (diumumkan), dugaan Gag
       -> _klaim_peran          klaim role, bentrok, pembohong
       -> _memihak_hitman
       -> per pemain: tekanan, dukungan, plin_plan, alihkan_tuduhan, menuduh_orang_baik,
          penuduh_dibungkam, ikut_salah_eksekusi, memihak_hitman, klaim_role_bermasalah, diam
       -> _konteks_permainan    warga_terdesak, chat_membingungkan, chat_sepi, bot_dituduh_baru, penanya, ...
  -> tabel bukti + konteks

Kode

Yang tidak terlihat dari kode

  • Hitman menghitung tabel kedua dengan hitung_bukti(..., publik=True): sudut pandang pengamat netral tanpa pengetahuan pribadi. Tabel itu menjadi bahan [FUZZY 1] Hitman.

3[FUZZY 1]

Bukti per pemain dinilai sistem Mamdani bertingkat. Warga menghasilkan kecurigaan, Hitman menghasilkan ancaman dan kambing hitam. Pohon sistemnya ada di Bedah Otak Fuzzy bagian 9.

Alur

Warga:  nilai_kecurigaan(tabel)
          -> tiap pemain: sistem HIERARKI berurutan, fuzzy(nama, a, b) / 100
          -> kecurigaan_mentah × (1 − p_sandera)
Hitman: nilai_kecurigaan(tabel publik)            kecurigaan publik
          -> fitur_hitman    menuduh_tim, pengaruh, mengaku_role_penting, kredibilitas, jejak_tuduhan, ...
          -> nilai_ancaman   ancaman_langsung, ancaman_peran, ancaman, kambing_hitam
fuzzy(nama, a, b)
  -> _fuzzy_tersimpan       simulasi skfuzzy yang dibangun sekali (SIMULASI)
  -> centroid 0–100

Kode

Yang tidak terlihat dari kode

  • Hasil skfuzzy disimpan lru_cache per (sistem, a, b), dengan input dibulatkan 4 desimal, jadi logika satu langkah bot hanya beberapa milidetik.
  • Kurva dan aturan semua sistem ada di Bedah Otak Fuzzy bagian 6.

4[KECURIGAAN DAN ANCAMAN]

Fakta pasti menimpa hasil [FUZZY 1], lalu pemain diurutkan. Urutan ini yang dibaca semua calon tindakan.

Alur

Warga:  terapkan_pengetahuan
          -> hasil Peek Hitman: 1 · pasti orang baik: 0 · diklaim bersih: × (1 − bersih_klaim)
        -> urutan_tersangka -> urutkan_kandidat    kecurigaan, lalu bukti_total, lalu nama
        -> Spy: fitur_lindung                      terancam per pemain
Hitman: urutan menurut kambing_hitam, lalu nama
keunggulan_skor: (tersangka #1 − #2) ÷ 0,30

5[CALON AKSI]

Calon dibuat dengan aturan biasa sesuai role, fase, dan izin. Sebagian langsung dipakai tanpa fuzzy, sisanya membawa input untuk [FUZZY 2]. Pembagiannya ada di Bedah Otak Fuzzy.

Alur

Vote:  keputusan_pindah_vote (seri) -> vote_pasti (hasil Peek) -> keputusan_vote_hitman atau keputusan_vote
Chat:  chat_pasti (Stalker tahu Hitman)                            langsung
       calon_chat
         -> _calon_chat_warga atau _calon_chat_hitman
              -> bela_diri (calon_bela_diri)                        langsung
              -> jawab (paket_jawab)                                langsung
              -> tuduh, bela_orang, tanya_info, ajak bicara          input [FUZZY 2]
         -> calon_ajak_vote (Tribunal)                              input [FUZZY 2]
Aksi:  calon_aksi
         -> calon_hostage   nilai_hostage, seri_acak               tanpa fuzzy
         -> calon_guard     terancam                               tanpa fuzzy
         -> calon_peek      intip                                  [FUZZY 2]
         -> calon_gag       gag                                    [FUZZY 2]

Kode

Yang tidak terlihat dari kode

  • Bila ada penuduh baru dan penanya sekaligus, hanya bela_diri yang dibuat (elif), jadi bela diri sekaligus menjawab.
  • Rekan Syndicate dan korban Hostage tidak ada di tabel fitur_hitman, jadi tidak pernah menjadi calon Hitman.

6[URUT DAN AMBANG]

Calon yang membawa input dinilai [FUZZY 2], diurutkan, lalu dibandingkan ambang. Arti ambangnya ada di Bedah Otak Fuzzy.

Alur

keputusan_chat
  -> tidak boleh inisiatif maupun reaktif: tunggu
  -> ada bela_diri atau jawab: langsung dipakai
  -> tiap calon: fuzzy(sistem, input) -> prioritas 0–100
  -> urut: prioritas, URUTAN_AKSI, jenis, nama target
  -> tertinggi ≥ AMBANG_CHAT: kirim
       \> di bawah ambang: calon_gali, selain itu tunggu
keputusan_vote
  -> keyakinan_vote -> kesiapan_vote
  -> ≥ VOTE_LANGSUNG, atau ≥ AMBANG_VOTE sesudah VOTE_TUNGGU_FRAKSI Tribunal: vote
       \> belum separuh: tunggu  \> ikut suara terbanyak  \> abstain
  -> pertahanan_suara: warga kritis tidak abstain
keputusan_aksi
  -> Gag dan Peek: fuzzy(sistem, input)
  -> urut: nilai, kunci seri, nama
  -> sudah memilih malam ini: rencana_pindah
  -> Gag: pilih_gag · lainnya: calon teratas

7[KEPUTUSAN]

putuskan menjalankan tahap di atas sekali per langkah dan menyatukan tiga rencana. format_npc mengubahnya menjadi paket untuk game.

Alur

putuskan(ingatan, view)
  -> hitung_bukti -> pengetahuan_peran -> [FUZZY 1]
  -> rencana vote -> pertahanan_suara
  -> rencana chat: chat_pasti atau keputusan_chat
  -> rencana aksi: keputusan_aksi
  -> format_npc         {action, target, message}: aksi rahasia, lalu vote, selain itu wait
  -> siapkan_nlg        payload kalimat, tanpa role asli
  -> siapkan_nlg_tim    paket chat tim malam, bila ada rekan manusia

Kode

8[NLG]

Rencana chat ditulis menjadi kalimat. LLM menulis bila aktif, dan kalimatnya diperiksa aturan. Bila LLM gagal atau kalimatnya ditolak, templat dipakai.

Alur

siapkan_nlg     payload: aksi, jenis, intent, target, role_diakui, bukti, batasan, cadangan
  -> NPCService._ambil_giliran_bicara     lantai bicara penuh atau rencana kembar: ditunda
  -> tulis_kalimat -> BrainRuntime.tulis -> tulis_pesan
       -> LLM: buat_prompt -> penulis.tulis -> nilai_kalimat (periksa_aturan) + kalimat_mirip
            \> lolos: kalimat dipakai
       -> templat: kalimat_templat, varian pertama yang lolos periksa_aturan
       -> cadangan: varian pertama
Chat tim malam: siapkan_nlg_tim -> tulis_kalimat_tim -> tulis_chat_tim

Kode

Yang tidak terlihat dari kode

  • Kalimat bot tidak dibaca ulang IndoBERT sebelum dikirim. Pemeriksanya hanya aturan teks (periksa_aturan) dan kemiripan dengan kalimat yang baru terdengar (kalimat_mirip).
  • Role asli bot tidak pernah masuk payload. LLM hanya menerima role_diakui dan bukti_klaim bila rencana memang membuka role.

9[KIRIM]

Vote dan aksi rahasia dikirim ke engine lebih dulu, lewat RoomService. Kalimat dikirim sesudah jeda mengetik, bila fase masih sama dan bot masih boleh chat.

Alur

NPCService.brain_turn
  -> _kirim_vote_atau_aksi -> RoomService.pilihan_bot -> terapkan_pilihan_bot
                                 Match.vote atau Match.act; pindah: pilihan lama dibatalkan dulu
  -> _kirim_chat_tim -> RoomService.chat_tim_bot      chat tim malam
  -> tulis kalimat -> jeda mengetik 1–4 detik
  -> RoomService.chat_bot -> record_bot_message -> Match.add_message
  -> BrainRuntime.catat_chat                           ingatan bot
  -> isi_jejak -> record_trace                         jejak panel Checker
  -> siaran receive_chat
  -> catat_nlu                                         kalimat bot dibaca IndoBERT untuk langkah bot lain
