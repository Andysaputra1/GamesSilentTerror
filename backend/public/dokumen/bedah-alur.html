1 Gambaran besar

Backend Silent Terror adalah satu aplikasi Python di folder backend/app/: FastAPI untuk HTTP dan Socket.IO untuk chat. Browser memakai dua jalur. HTTP membawa perintah seperti login, buat room, vote, dan survei. Socket.IO tetap terbuka dan membawa chat. Di dalam server ada jam permainan yang berdetak tiap 0,5 detik, memajukan fase, dan menjalankan bot tanpa menunggu browser.

Dokumen ini membedah kode dari main.py sampai ujung tiap fungsi. Bab 2 dan 3 mengikuti urutan bedah bersama pemilik proyek. Bab 4 sampai 10 dikelompokkan per fitur, dari controller sampai SQL. Nomor kecil di kanan judul kartu (misalnya 1.3) adalah letaknya di pohon bedah main.py.

Peta besar

Permintaan masuk dari atas dan turun lapis demi lapis. Controller dan socket tidak menulis SQL; hanya models/ yang berisi SQL, dan transaksinya dibuka lewat config/database.py. Room, pertandingan, dan jejak live ada di memori, jadi hilang saat server restart.

Kesimpulan akhir

Backend menyala dari main.py: impor file membuat Socket.IO, pengatur bot, dan semua router, lalu lifespan mengecek MySQL, memuat konfigurasi panel dan otak bot, dan menyalakan jam permainan. Sesudah itu tiga hal menggerakkan permainan: HTTP untuk perintah pemain dan panel, Socket.IO untuk chat, dan jam 0,5 detik untuk pergantian fase dan langkah bot.

Aturan permainan ada di satu tempat, game/match_engine.py, dan selalu dijalankan di bawah satu kunci untuk semua room (room_service.lock). Sebagian besar pemanggilan lewat services/room_service.py; chat dan survei memegang kunci yang sama. Bot memakai jalur yang sama dengan pemain. MySQL menyimpan akun, sesi, arsip room, chat beserta bacaan IndoBERT, jejak checker, dan survei; room dan pertandingan yang sedang berjalan hanya ada di memori.

Keadaan bedah: 12 bagian sudah dibahas bersama pemilik proyek (alur utama, logger, dan seluruh sambungan Socket.IO), 60 bagian belum dibahas, dan 0 ditunda.

Temuan dan risiko yang masih terbuka

  • Risiko di auth_service.check_user_by_token: Rumus hash ditulis langsung di 4 tempat atas permintaan user, semuanya di services/auth_service.py: login, fungsi ini, logout, dan issue_session. Kalau satu diubah sendiri, token yang sah tidak ketemu di DB dan pemain tertolak.
  • Temuan di SessionLocal: SessionLocal sinkron. Route HTTP biasa (def) dijalankan FastAPI di threadpool, jadi tidak menahan server. Yang menahan event loop, termasuk jam permainan, adalah query dari kode async (misalnya connect, tahap 3 chat, dan chat_bot dari langkah bot) dan query yang jalan sambil memegang room_service.lock, karena jam menunggu kunci itu. Dampak nyatanya dibahas di [[emit_room]].
  • Temuan di chat_service.kirim_chat_pemain: Tahap 3 menulis ke MySQL sambil memegang room_service.lock, dan lock itu satu untuk semua room. Ini disengaja supaya Gag atau fase baru tidak diterobos, tapi operasi room lain menunggu selama itu. Durasinya belum diukur.
  • Temuan di emit_room: Setiap chat menjalankan [[auth_service.check_user_by_token]] untuk tiap socket di room, jadi 1 chat berarti 1 query per pemain. SessionLocal sinkron, jadi server menunggu selama query jalan, termasuk jam permainan. Dengan beberapa pemain dampaknya kemungkinan kecil, tapi belum diukur. Saranku jangan diubah sebelum diukur.
  • Risiko di panel_service: CSV riwayat chat (GET /api/panel/history.csv) sengaja menulis teks pemain apa adanya, karena dipakai sebagai dataset NLU. Saat dibuka di spreadsheet, impor kolom teks sebagai teks supaya tidak dijalankan sebagai formula.
  • Temuan di survey_service.submit: Pesan 503 di survey_call selalu berbunyi "Database survei belum siap. Jalankan migrasi V7.", juga saat MySQL mati atau migrasi lain (V10 sampai V12) yang kurang. Pesan ini bisa menyesatkan saat mencari penyebab.
